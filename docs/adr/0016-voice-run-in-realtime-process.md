# v1은 음성 서버를 실시간 서버 프로세스 안에서 돌린다

승인 | YYYY-MM-DD | 관련 RFC: 없음

## 상황

실시간 서버는 클라이언트와 WebSocket으로 연결해 접속 인증, 면접방, 아바타 움직임, 채팅을 맡는다. 음성 서버를 같은 프로세스에 둘지 별도 서버로 둘지 정해야 한다. WebRTC 표준은 offer와 answer를 주고받는 시그널링 방법을 정하지 않는다.

## 결정

- v1은 실시간 서버 프로세스 하나 안에 음성 서버를 둔다.
- 시그널링은 실시간 서버의 WebSocket 연결을 그대로 쓴다.
- 시그널링 모듈과 미디어 모듈 사이의 계약은 `media` 패키지로 따로 둔다. 미디어 모듈을 별도 서버로 떼어 낼 때 같은 계약을 원격 호출로 구현해 갈아 끼운다.

## 이유

- 접속 인증과 방 구성원 정보를 실시간 서버가 이미 갖고 있어, 음성 서버가 따로 확인할 필요가 없다.
- 운영할 프로세스와 시그널링 채널이 하나씩 줄어든다.
- 방 하나가 최대 약 800kbps라 v1 규모는 서버 한 대로 충분하다. 분리 시점은 부하 테스트와 실제 사용량으로 정한다.
- 계약을 시그널링 모듈 쪽에 두면 미디어 모듈이 계약을 쓰려고 시그널링 모듈을 import해야 한다. 계약을 따로 두면 두 모듈이 서로를 모르고, 시그널링 모듈을 Pion 없이 가짜 미디어 구현으로 테스트할 수 있다.

## 결과

- 얻는 것: 배포와 운영이 단순하다. 시그널링 채널을 새로 만들지 않는다.
- 감수하는 것: 서버를 재시작하면 진행 중인 면접의 음성이 몇 초간 끊기고, 음성과 무관한 기능을 배포할 때도 마찬가지다. 그래서 면접이 없는 시간에 배포한다. 음성 연결 상태가 프로세스 메모리에만 있어 재시작하면 모든 참가자가 다시 연결한다.
