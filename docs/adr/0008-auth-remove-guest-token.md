# 게스트 토큰을 발급하지 않고 로비는 공개 조회로 연다

승인 | 2026-11-24 | 관련 RFC: 없음

## 상황

처음 설계는 비회원이 로비에 들어오면 core가 2시간짜리 게스트 JWT(`roles: [GUEST]`)를 발급했다. 리뷰에서 "비회원이 로비에서 하는 게 없는데 왜 토큰이 필요한가"라는 질문이 나왔다.

## 결정

- 게스트 토큰을 발급하지 않는다. `POST /api/v1/auth/guest`와 `GUEST` 역할을 없앤다
- 로비 정보는 인증 없는 공개 조회 API로 준다. 자세한 API는 로비 설계에서 정한다
- 인증은 "보기"가 아니라 "행동"(예약, 면접방 입장 등)에 요구한다
- realtime WebSocket은 회원만 연결한다

## 이유

- 토큰은 "누구인가(인증)"와 "무엇을 해도 되나(인가)"에 쓴다. 게스트는 확인할 신원도, 허락할 행동도 없다
- 게스트 토큰은 누구나 받을 수 있어서 남용 방지에도 도움이 되지 않는다. 남용은 IP별 요청 제한으로 막는다
- 서버가 게스트 A와 B를 구분해야 하는 기능(게스트 접속자 표시, 새로고침 후 같은 자리 유지 등)이 없다
- 토큰을 주면 발급 API, 요청 제한, 만료 후 재발급 흐름, `GUEST` 권한 규칙이 모두 생긴다

## 결과

- 얻는 것: 엔드포인트 하나와 역할 하나가 줄어든다. realtime은 "회원 토큰" 한 가지만 검증한다
- 감수하는 것: 나중에 게스트를 구분해야 하는 기능이 생기면 다시 정해야 한다. 그때도 JWT보다 서버가 발급하는 랜덤 게스트 ID로 충분한지 먼저 본다
