# 방 역할은 토큰에 넣지 않고 예약 데이터에서 받는다

승인 | 2026-11-24 | 관련 RFC: 없음

## 상황

같은 사람이 어떤 방에서는 면접관, 다른 방에서는 면접자가 된다. realtime은 방 안에서 "질문 넘기기는 면접관만" 같은 권한을 판단해야 한다.

## 결정

- 토큰의 `roles`에는 계정 단위 역할(`MEMBER`, `ADMIN`)만 넣는다
- 방 역할(`INTERVIEWER`, `INTERVIEWEE`)은 예약할 때 `reservation`에 저장한다
- 면접이 시작되면 realtime이 core에 gRPC `GetParticipants`로 참가자 목록을 받아 메모리에 두고, 면접이 끝날 때까지 쓴다
- 화면·채팅·음성 메시지에는 회원 ID 대신 realtime이 입장 때 부여하는 방 참가자 ID를 쓴다

## 이유

- 역할을 토큰에 넣으면 방마다 다른 토큰을 발급해야 하고, 예약이 바뀌면 토큰과 어긋난다
- 한 방 안에서 역할은 바뀌지 않으므로 시작 때 한 번 받으면 충분하다. 메시지마다 core에 물을 필요가 없다
- 회원 ID를 상대에게 보내면 같은 방 사람에게 노출된다

## 결과

- 얻는 것: 토큰은 계정 하나에 하나로 단순하다. 방 안 권한 판단은 realtime 메모리에서 끝난다
- 감수하는 것: realtime → core gRPC 호출이 생긴다. 이 호출의 인증이 필요하다 ([gRPC 인증 결정](auth-grpc-shared-token.md))
